## Implementation change

`AccountLifecyclePanel.tsx` previously enabled generation after a failed initial history read and after an ambiguous export POST without first recovering durable jobs. It now requires a successful requester-history read, automatically performs that read after POST failure, and offers **Refresh exports**. Existing active-job polling and server-authoritative expiry/download remain. Export copy explicitly includes time cards and payroll.

This is recovery guidance, not a new server idempotency guarantee. A history read cannot prove that a still-running original POST will never commit later; tenant admission remains the server's authority. No automatic repeat POST is added. ## Source review follow-up (2026-10-09)

The original patch lacked synchronous exclusion and response lifetime checks. The revised `AccountLifecyclePanel.tsx` uses refs to reject a second start before React renders, serializes history recovery, invalidates older poll responses when recovery starts, and aborts/ignores export responses after unmount, permission change or recorded deletion. Recovery after a failed POST is explicitly allowed while that start retains its synchronous guard; ordinary refresh cannot race the start. Only the owning lifetime clears busy state. Polling resumes after a superseded read rather than silently ending.

`apps/web/app/dashboard/settings/page.tsx` now keys SettingsWorkspace by the existing server-auth `workspaceScope`, `publicUserId` and `sessionScope`. A delivered server identity change remounts the workspace and disposes its old account panel. This intentionally discards drafts on identity/session replacement; it does not discard drafts during an ordinary same-identity refresh. These are existing opaque UI scope fields, not raw credentials. No new props or server contract are introduced.

Caller/server inspection:

- `SettingsWorkspace.tsx` conditionally mounts AccountLifecyclePanel only on the Account tab. Leaving/re-entering that tab therefore requires cancellation/late-response exclusion and fresh durable history recovery.
- `client-api.ts` propagates caller AbortSignal, blocks requests after `prepareForLogout`, and does not replay this unsafe POST after authentication refresh because it has no Idempotency-Key. Abort is not evidence of server rollback.
- `TenantExportService.startAdmitted` creates a new random job ID per POST, uses a transaction and tenant admission/rate limits. `listRecent` returns only the requesting tenant/user's five most recent unexpired jobs. Empty history cannot prove a pending original POST will never commit, and cannot recover another administrator's job. No exactly-once guarantee or indefinite history is added.
- Known boundary: an identity change in another tab that has not delivered new server props/full navigation to this document is not detected by the React key itself. The existing session client and server authorization remain required; this patch does not add cross-tab identity infrastructure.
